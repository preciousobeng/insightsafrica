Review and merge the combined branch instead of those two earlier branches.
The forecast-ordering, page-verification, and password-recovery branches remain independent.

## What changed

- One migration removes the live PUBLIC telemetry policy and client table/column grants, preserving backend logging.
- Signup always creates a free profile. Profile tier/id/creation-time changes are no longer client-writable; name, email, and birth-date edits remain available under ownership RLS.
- Clients cannot insert, update, or delete API-key rows directly. Authenticated create/revoke RPCs bind actions to the caller.
- A shared insertion trigger validates names and SHA-256 hashes, initializes new keys as free with zero usage, and serializes creation using the owning profile row. Both RPC and legacy HTTP callers obey the five-active-key cap.
- Only the service role may call the quota-consumption function, preventing clients from supplying their own limit.
- The Ghana hub creates/revokes keys through the RPCs. It preserves the existing `ia_` + 32 random bytes/base64url format and SHA-256 storage contract. Only the hash is sent to Supabase.
- HTTP API-key verification handles the table-returning RPC correctly. Database cap rejections return HTTP 429.
